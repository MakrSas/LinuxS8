# Графическое ускорение

> Обновлено 2026-08-06. Решение принято: идём через bring-up Panfrost для
> Mali-G71 в mainline (а не через Halium/libhybris). Обоснование — ниже и в
> [risks-and-open-questions.md](risks-and-open-questions.md).

## Цель

Аппаратное 3D-ускорение (OpenGL ES, в идеале Vulkan) для комфортной работы
GNOME Shell / Mutter поверх Wayland на этом телефоне.

## Выбранный путь: bring-up Panfrost для Mali-G71 (Bifrost gen1)

По официальной документации Mesa/Panfrost (docs.mesa3d.org, проверено
2026-08-06) Mali-G71 сейчас **не поддерживается**: конформны только
Mali-G52/G57/G610, из Bifrost — G72, G31, G51, G52, G76. Дословно: "Other
Midgard and Bifrost chips (e.g. G71) are not yet supported."

**Почему всё равно этот путь, а не Halium/libhybris:**

- G71 — тот же Bifrost gen1, что и уже поддерживаемый G72: это расширение
  существующего работающего драйвера, а не создание нового с нуля.
- Если Panfrost заработает — Mutter получает GPU через штатный, родной для
  него путь (DRM/KMS + GBM), без дополнительного кода на стороне
  компоузера. У Halium-варианта пришлось бы **самим с нуля** писать
  hwcomposer-бэкенд для Mutter — такого не делал никто и никогда, даже для
  KDE (единственная попытка, `kwin-hybris`, заброшена с мая 2022).
- Остаётся полностью открытым (без проприетарных Mali-блобов) — не мешает
  цели открыть код для всех.
- Результат может уйти в апстрим Mesa и закрыть эту дыру не только для нас.

**Компромисс, который мы сознательно принимаем:** периферию (тачскрин,
звук, WiFi/BT, GPS, зарядка и т.д.) всё равно придётся портировать в
mainline отдельно — в отличие от Halium, где часть этого уже готова
(рабочий, хоть и старый, порт 2022 года, см. [prior-art.md](prior-art.md)).
Мы отказываемся от этой готовой периферии в пользу более чистого GPU-пути.

## План работ

1. **Получить initramfs shell на mainline-ядре через uniLoader** (план A в
   [boot-chain.md](boot-chain.md)) — предпосылка для всего остального, без
   этого негде тестировать GPU-драйвер. Ещё не начато.
2. Проверить, что уже есть в drm/panfrost (ядро) по части поддержки GPU ID
   Mali-G71 — kernel-side драйвер Panfrost во многом общий для
   Midgard/Bifrost/Valhall чипов, разрыв в поддержке G71 может быть в
   основном на стороне компилятора/userspace (Mesa), а не самого DRM-модуля
   ядра. Это нужно перепроверить на актуальном исходном коде перед стартом
   — не закладываться на предположение без проверки.
3. Добавить/поправить device tree узел GPU для dreamlte (в mainline DTS его
   пока нет — принята только минимальная поддержка SoC, см.
   [prior-art.md](prior-art.md)): clocks, power domain, регистры Mali-G71.
4. Работа над Mesa/Panfrost userspace-частью (компилятор шейдеров под
   ISA Bifrost gen1, если для G71 есть отличия от G72) — самая
   неопределённая по объёму часть, вероятно потребует общения с апстрим
   Panfrost-командой (gitlab.freedesktop.org/panfrost) на предмет того, что
   уже пробовали и почему G71 остался не портирован, когда G72 — да.
5. Поставить/собрать Mesa с включённым Panfrost (актуальная версия из
   исходников, пока патчи не в апстриме).
6. Настроить KMS под панель S8 (DSI, 2960×1440) — потребуется собственный
   DRM-панель драйвер, панели в mainline-ядре пока нет.
7. Проверить работу Wayland/Mutter поверх panfrost + kmsdrm.
8. Профилировать производительность; настроить governor и учесть тепловой
   троттлинг — устройство без активного охлаждения, узкое место.

## Параллельная задача: периферия в mainline-ядре

Не блокирует GPU-работы, но нужна для реального использования телефона:
тачскрин, звук, WiFi/BT, зарядка, сенсоры — см. таблицу в
[prior-art.md](prior-art.md). Часть можно портировать, опираясь на
downstream-драйверы (opensource.samsung.com, `exynos-linux-stable/dreamlte`)
как референс.

## Отклонённая альтернатива: Halium/libhybris

Задокументирована для истории и на случай пересмотра решения — см.
[prior-art.md](prior-art.md) раздел 4 и
[boot-chain.md](boot-chain.md) план B. Даёт рабочий, протестированный мост к
GPU через Android HAL, но не даёт GNOME/Mutter без написания нового
hwcomposer-бэкенда для Mutter с нуля — сопоставимый объём R&D, но менее
"чистый" результат (проприетарный blob, старое downstream-ядро). Решение —
не идти этим путём, зафиксировано 2026-08-06.

## Открытые вопросы

- Точный объём работы над Panfrost для G71 — неизвестен до начала: сколько
  в drm/panfrost уже общее, сколько специфично для G72 и потребует
  добавления GPU ID/quirks для G71, сколько работы в компиляторе Mesa.
- Стоит ли начинать общение с апстрим Panfrost-командой заранее (до
  начала практической работы), чтобы не делать параллельно то, что уже
  кто-то пробовал.
- Насколько стабилен тачскрин-стек, когда дойдём до параллельной задачи по
  периферии.
