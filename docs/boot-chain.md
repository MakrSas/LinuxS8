# Цепочка загрузки (boot chain)

> Обновлено 2026-08-06 по итогам исследования существующих наработок —
> см. [prior-art.md](prior-art.md) за источниками.

## План A (основной, доступен уже сейчас): uniLoader + mainline-ядро

Не нужно ждать сторонних исходников — конкретно под dreamlte уже существует
рабочая связка:

1. **uniLoader** (https://github.com/ivoszbg/uniLoader) как вторичный
   загрузчик — обходит проприетарный Samsung S-Boot, упаковывает и
   загружает kernel + DTB + initramfs.
2. **mainline-ядро kernel.org** с минимальной поддержкой Exynos8895/
   SM-G950F (принята в 2024) — CPU, pinctrl, GPIO, simple-framebuffer,
   pstore. Этого достаточно для initramfs shell, не для полноценной
   периферии.

Этапы:

1. Собрать uniLoader и mainline-ядро (актуальная версия) с DTB для dreamlte.
2. Сделать TWRP-бэкап, затем стереть текущие попытки Windows 11 ARM с
   телефона.
3. Прошить/загрузить через uniLoader, добиться initramfs shell на
   mainline-ядре.
4. Дальше — расширять поддержку периферии в ядре (тачскрин, звук, WiFi/BT,
   GPS и т.д. — пока отсутствуют в mainline, см. [prior-art.md](prior-art.md)),
   и разворачивать полноценный Debian rootfs (debootstrap) поверх.
5. По желанию — позже добавить GRUB2 (arm64) поверх uniLoader/ядра для более
   привычного UEFI-подобного флоу установки/выбора ОС.

GPU-ускорение в этом плане упирается не в загрузку, а в отсутствие
поддержки Mali-G71 в Panfrost — это решается отдельным bring-up'ом (см.
[graphics.md](graphics.md)), не блокирует старт работ по загрузке.

## План B (отклонён, 2026-08-06): downstream-ядро + Halium/libhybris

Рассматривался как путь к рабочей периферии/GPU здесь и сейчас через
существующий (хоть и заброшенный с 2022) Halium-порт. Отклонён в пользу
плана A + bring-up Panfrost — причины решения см.
[risks-and-open-questions.md](risks-and-open-questions.md#1-решено-2026-08-06-идём-через-bring-up-panfrost-для-mali-g71-не-через-halium)
и [graphics.md](graphics.md). Оставлено здесь для истории/справки — детали
в [prior-art.md](prior-art.md).

## План C (запасной, низкий приоритет): переиспользование стороннего UEFI

Если позже понадобится полноценный UEFI-флоу (например, для
дуал-бута/привычного инсталлятора) — можно рассмотреть готовый UEFI,
написанный под другое Exynos-устройство, и адаптировать под S8. Не является
приоритетом, так как план A уже даёт рабочий путь загрузки без внешних
зависимостей.

## Статус

**Достигнуто (2026-08-07):** план A работает на реальном железе — uniLoader
успешно грузит mainline-ядро 7.2.0-rc6, initramfs стартует, лог загрузки
виден на экране телефона через DRM/SimpleDRM. Подробности, включая
исправленные по пути проблемы (тулчейн, размер образа), — см.
[progress-log.md](progress-log.md#2026-08-07--первая-успешная-загрузка-mainline-ядра-на-dreamlte).

Тачскрин/клавиатура в mainline ещё не портированы — интерактивности пока
нет, только наблюдение через экран/лог. Дальше — расширение периферии и/или
debootstrap Debian rootfs поверх initramfs.
