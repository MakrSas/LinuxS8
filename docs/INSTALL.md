# Установка чистого Debian

`scripts/installer.py` готовит новый Debian arm64 rootfs и записывает его на
Samsung Galaxy S8 (`dreamlte`). Текущий rootfs телефона не читается как
шаблон: обои, настройки, журналы и пользовательские файлы в новый образ не
попадают.

Установщик по шагам:

1. предлагает выбрать Debian `trixie`, `bookworm` или `stable`;
2. предлагает Phosh или экспериментальный GNOME;
3. предлагает масштаб интерфейса — по умолчанию 300%;
4. спрашивает имя аккаунта и пароль (пароль не печатается и не коммитится);
5. скачивает пакеты с официального зеркала Debian и собирает чистый rootfs;
6. ждёт, пока телефон появится именно в TWRP;
7. предлагает сохранить локальный бэкап `sda7` и `sda29`;
8. требует точную фразу `FORMAT sda29` перед форматированием;
9. распаковывает rootfs на ext4 `sda29` с меткой `linuxroot`;
10. требует точную фразу `FLASH sda7` перед прошивкой boot-образа;
11. сверяет boot-образ побайтно через ADB readback перед перезагрузкой.

Длинные выводы `apt`, debootstrap и настройки rootfs не засоряют терминал:
на экране остаются только этапы установки. Полный журнал пишется в
`build/installer/*.log`; при ошибке процесс сразу завершается и показывает
последние строки журнала.

Форматирование и прошивка не выполняются автоматически при запуске. Если
телефон не в TWRP, установщик не ошибается и не переключает разделы — он
продолжает ждать.

## Linux

Нужны `python3`, `debootstrap`, `qemu-user-static`, `binfmt-support` и ADB.
Для x86_64 обычно достаточно:

```bash
sudo apt install python3 debootstrap qemu-user-static binfmt-support adb
python3 scripts/installer.py
```

Существующий локальный boot-образ из этого рабочего дерева определяется
автоматически: сначала `build/device-backups/boot_safe-battery-fixed.img`.
Если рядом есть `build/src/linux`, установщик также добавляет в новый rootfs
модули именно этого ядра, чтобы boot и rootfs были согласованы.
Можно указать другой явно:

```bash
python3 scripts/installer.py --boot-image /path/to/boot.img
```

## Windows

Запускатель нативный:

```powershell
.\scripts\installer.ps1
```

ADB и прошивка выполняются в Windows. Сборка arm64 Debian требует WSL2,
потому что в Windows нет `debootstrap` и Linux `chroot`; установщик сам
передаёт только этот этап в WSL. В WSL один раз установите:

```bash
sudo apt update
sudo apt install python3 debootstrap qemu-user-static binfmt-support
```

Для обнаружения TWRP Windows также должен иметь USB-драйвер Samsung/ADB.
Проверка перед установкой: `adb devices` должна показывать телефон.

Если ADB не установлен, установщик скачивает официальные Google
platform-tools в локальный каталог `build/installer-cache/`.

## Boot-образ

Boot-образ содержит kernel/DTB/initramfs, а не личный rootfs. Для локальной
проверки его можно передать через `--boot-image`. После публикации проверенной
сборки можно использовать URL релиза:

```bash
python3 scripts/installer.py --boot-url https://.../boot.img
```

Пока стабильный публичный URL boot-образа не закреплён, публичный клон
репозитория сможет собрать чистый Debian, но для полной установки ему нужно
явно указать совместимый boot-образ. Это намеренное ограничение до проверки
образа на реальном телефоне.

## Что не публикуется

В Git не попадают `build/`, rootfs, образы разделов, бэкапы, ключи, пароли,
архивы и журналы. Локальный бэкап `sda29` может содержать личные данные — его
нельзя отправлять в GitHub или прикладывать к issue. Новый rootfs всегда
создаётся из официального Debian, с новым `machine-id`, уникальными SSH
host-ключами и без пользовательских обоев/настроек.
